=== The description of every object that the YAML files and the script create
KIND                      NAME                DESCRIPTION
Deployment                processor           Reads network flow messages from Kafka and stores them in MongoDB. Stateless; its replica count belongs to the HorizontalPodAutoscaler (1 to 3)
Deployment                restapi             REST API that serves the stored flows from MongoDB: /health, /ready, /stats, /alerts and /events/TRACE_ID. Two stateless replicas
StatefulSet               kafka               Kafka broker in KRaft mode (no ZooKeeper), one node. New topics get 3 partitions. Messages are kept on a PersistentVolumeClaim
StatefulSet               mongo               MongoDB 7 with its data on a PersistentVolumeClaim. The administrator name and password are read from files mounted from the Secret mongo-credentials
Job                       producer-replay     The producer stage of the stack: replays the 5,000-row dataset into Kafka once and ends. Delete the Job and apply again to replay
Job                       producer-smoke      Sends one tagged event through the pipeline for make smoke. Not part of make up
HorizontalPodAutoscaler   processor           Keeps the processor between 1 and 3 pods and adds pods above 70 percent CPU. The maximum is 3 because the topic has 3 partitions
Service                   kafka               Address of the Kafka broker inside the cluster (kafka:9092). Not reachable from outside the cluster
Service                   kafka-headless      Gives the Kafka StatefulSet pod a stable DNS name (kafka-0.kafka-headless) instead of a virtual IP. Kafka advertises this name to its clients
Service                   mongo               Address of MongoDB inside the cluster (mongo:27017). Not reachable from outside the cluster
Service                   mongo-headless      Gives the MongoDB StatefulSet pod a stable DNS name (mongo-0.mongo-headless) instead of a virtual IP
Service                   processor           ClusterIP Service for the processor's health and metrics port (8000). Only pods labelled component observer may call it
Service                   restapi             The only Service published outside the cluster: node port 30080 on every node, forwarding to port 8080 of the REST API pods
ConfigMap                 kube-root-ca.crt    <none>
ConfigMap                 pipeline-config     Settings shared by the producer, processor and REST API: Kafka address and topic, MongoDB address, database and collection, REST port and dataset file
ConfigMap                 processor-config    Settings only the processor needs: its Kafka consumer group and the port of its health and metrics server
NetworkPolicy             allow-dns-egress    Lets every pod ask the cluster DNS (CoreDNS in kube-system, port 53) to turn a Service name into an address
NetworkPolicy             default-deny-all    Blocks all traffic into and out of every pod in the namespace. The other policies then allow, one by one, only the connections the pipeline needs
NetworkPolicy             kafka-ingress       Kafka accepts connections only from the producer and the processor, on port 9092
NetworkPolicy             kafka-self          The Kafka pod may talk to itself on ports 9092 and 9093 (broker and controller)
NetworkPolicy             mongo-ingress       MongoDB accepts connections only from the processor and the REST API, on port 27017
NetworkPolicy             observer-egress     Pods with the label component=observer (the role of a monitoring tool; make netpol-check plays it) may call only the processor's port 8000 and the REST API's port 8080
NetworkPolicy             processor-egress    The processor may connect only to Kafka (port 9092) and MongoDB (port 27017)
NetworkPolicy             processor-ingress   The processor's metrics port 8000 may be read only by pods labelled component observer
NetworkPolicy             producer-egress     The producer may connect only to Kafka, on port 9092
NetworkPolicy             restapi-egress      The REST API may connect only to MongoDB, on port 27017
NetworkPolicy             restapi-ingress     The REST API accepts connections on port 8080 from any source. The AWS firewall limits who can reach the node port in front of it
ServiceAccount            default             <none>
ServiceAccount            kafka               Identity of the Kafka pod. Its Kubernetes API token is not mounted, because Kafka never calls the Kubernetes API
ServiceAccount            mongo               Identity of the MongoDB pod. Its Kubernetes API token is not mounted, because MongoDB never calls the Kubernetes API
ServiceAccount            pipeline-operator   Can run the producer and scale the pipeline, but cannot read Secrets
ServiceAccount            pipeline-viewer     Read-only access to the pipeline
ServiceAccount            processor           Identity of the processor pods. Its Kubernetes API token is not mounted, because the processor never calls the Kubernetes API
ServiceAccount            producer            Identity of the producer Jobs and pods. Its Kubernetes API token is not mounted, because the producer never calls the Kubernetes API
ServiceAccount            restapi             Identity of the REST API pods. Its Kubernetes API token is not mounted, because the REST API never calls the Kubernetes API
Role                      pipeline-operator   Everything the viewer can read, plus create and delete Jobs and change the replica count of a Deployment. Secrets are not included
Role                      pipeline-viewer     Read-only: pods, logs, Services, ConfigMaps, volume claims, events, workloads, Jobs, autoscalers and network policies. Secrets are not included
RoleBinding               pipeline-operator   Gives the Role pipeline-operator to the ServiceAccount pipeline-operator
RoleBinding               pipeline-viewer     Gives the Role pipeline-viewer to the ServiceAccount pipeline-viewer
Secret                    mongo-credentials   MongoDB administrator name and password. Made by scripts/create-secrets.sh and never stored in git. Mounted as read-only files into mongo, processor and restapi
